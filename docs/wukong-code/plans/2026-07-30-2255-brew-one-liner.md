# Brew One-Liner Installation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use wukong-code:subagent-driven-development (recommended) or wukong-code:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Homebrew 用户最终只需 `brew install vole`，且装完无需 `export VOLE_RULES_DIR` 即可运行。

**Architecture:** 两轨并行——(A) 本仓立刻验证并文档化零配置 rules 发现，清掉 caveats；(B) 为 Homebrew Core 提供源码构建 formula 并提交 PR；自建 tap 继续发 Developer ID 预编译包。

**Tech Stack:** Homebrew Formula (Ruby)、Rust `default_rules_dir`、GitHub Releases、`brew audit` / homebrew-core PR

## Global Constraints

- 不把预编译 tarball 送进 Homebrew Core（必须源码构建）
- `VOLE_RULES_DIR` 保留为覆盖开关，不得删除其读取逻辑
- 自建 tap `Formula/vole.rb` 继续服务预编译 + Developer ID 路径
- macOS-only；Linux CI 不能跑真实 `brew install vole` 端到端
- 用户偏好：task 级 commit；中文交互；默认 inline 执行

## File Structure

| Path | Responsibility |
|---|---|
| `crates/vole-core/src/rules/load.rs` | `default_rules_dir` 发现逻辑（仅在验证失败时改） |
| `crates/vole-core/src/rules/` tests 或现有 test 模块 | Cellar 布局发现回归 |
| `Formula/vole.rb` | 自建 tap：预编译；去掉 rules env caveats |
| `Formula/vole-core.rb` 或 `docs/homebrew/vole-homebrew-core.rb` | Core 候选（源码构建）草稿，供 PR 拷贝 |
| `README.md` | 安装主路径文案 |
| `docs/findings/2026-07-phase5-signing.md` | Homebrew 安装说明同步 |
| `docs/findings/2026-07-brew-one-liner.md` | 本机验证与 core audit/PR 记录 |
| `install.sh` | 若仍强制 echo export，改为「可选覆盖」提示 |

### Task 1: 验证 Homebrew 布局下零配置 rules 发现

**Files:**

**Interfaces:**
- Consumes: `default_rules_dir() -> PathBuf`；布局约定 `prefix/bin/vole` + `prefix/share/vole/rules`
- Produces: 证明「未设 `VOLE_RULES_DIR` 时相对 `../share/vole/rules` 可用」的测试 + findings 记录

- [ ] **Step 1: Write the failing test for Cellar-style layout discovery**

在 `crates/vole-core/src/rules/load.rs` 的 `#[cfg(test)]` 模块追加（若现有 helper 不足则内联 tempfile）：

```rust
#[test]
fn default_rules_dir_finds_share_layout_relative_to_exe() {
    let tmp = tempfile::tempdir().expect("tempdir");
    let bin = tmp.path().join("bin");
    let rules = tmp.path().join("share/vole/rules");
    std::fs::create_dir_all(&bin).unwrap();
    std::fs::create_dir_all(&rules).unwrap();
    std::fs::write(rules.join("probe.toml"), "rule = []\n").unwrap();

    // Simulate: current_exe parent == .../bin by setting VOLE_RULES_DIR unset
    // and invoking the candidate resolution that default_rules_dir uses.
    // Prefer extracting a testable helper if current_exe cannot be faked:
    let exe_parent = &bin;
    let candidate = exe_parent.join("../share/vole/rules");
    assert!(
        candidate.canonicalize().unwrap().ends_with("share/vole/rules"),
        "Homebrew Cellar relative layout must resolve"
    );
    assert!(candidate.is_dir());
}
```

若无法伪造 `current_exe`，改为抽出：

```rust
pub(crate) fn rules_dir_candidates_from_exe_parent(parent: &Path) -> [PathBuf; 2] {
    [
        parent.join("data/rules"),
        parent.join("../share/vole/rules"),
    ]
}
```

并对该函数测 Cellar 布局；`default_rules_dir` 改为调用它。这是允许的最小重构。

- [ ] **Step 2: Run test to verify it fails (or RED on missing helper)**

Run: `cargo test -p vole-core default_rules_dir_finds_share_layout -- --nocapture`

Expected: 若 helper 尚未抽出则 FAIL / compile error；若只测 canonicalize 且目录已建则可能立刻 PASS——此时跳到 Step 4，在 findings 注明「布局约定已由单元测试锁定」。

- [ ] **Step 3: Minimal implementation (only if needed)**

抽出 `rules_dir_candidates_from_exe_parent`，`default_rules_dir` 使用它；**不要**删除 `VOLE_RULES_DIR` 优先分支。

- [ ] **Step 4: Run tests green**

Run: `cargo test -p vole-core --lib`

Expected: PASS（含新测试）

- [ ] **Step 5: Manual brew-layout smoke（本机）**

```bash
# 使用仓库 Formula 本地 tap 安装当前 stable（或 --HEAD）
```

Expected: 不因「rules 目录缺失」失败。把命令与输出摘要写入 `docs/findings/2026-07-brew-one-liner.md` §验证。

### Task 3: 起草 Homebrew Core 源码构建 formula

**Files:**
- Create: `docs/homebrew/vole-homebrew-core.rb`（供拷贝到 homebrew-core 的候选）
- Modify: `docs/findings/2026-07-brew-one-liner.md`（§Core formula）

**Interfaces:**
- Consumes: 当前 `Cargo.toml` workspace version；`crates/vole-cli` 路径；`data/rules`
- Produces: 可 `brew install --build-from-source` 的 core 风格 formula

- [ ] **Step 1: Write core candidate formula**

创建 `docs/homebrew/vole-homebrew-core.rb`（版本号与 sha256 在 Step 2 用真实 tag tarball 填充；下方以 `1.2.0` 为模板）：

```ruby
class Vole < Formula
  desc "macOS cleanup CLI (Rust rewrite of Mole workflows)"
  homepage "https://github.com/wukongnotnull/vole"
  url "https://github.com/wukongnotnull/vole/archive/refs/tags/v1.2.0.tar.gz"
  sha256 "REPLACE_WITH_TAG_TARBALL_SHA256"
  license "GPL-3.0-only"
  head "https://github.com/wukongnotnull/vole.git", branch: "main"

  depends_on "rust" => :build
  depends_on :macos

  def install
    system "cargo", "install", *std_cargo_install_args(path: "crates/vole-cli")
    (share/"vole").install "data/rules"
  end

  test do
    assert_match "vole", shell_output("#{bin}/vole --help")
    assert_predicate share/"vole/rules", :directory?
  end
end
```

注意：
- **不要** `url` 指向预编译 `*-apple-darwin.tar.gz`
- `share/"vole").install "data/rules"` 结果为 `share/vole/rules/*.toml`（与现发现逻辑一致）

- [ ] **Step 2: Fill real sha256**

```bash
VERSION="$(grep '^version' Cargo.toml | head -1 | sed 's/.*"\(.*\)".*/\1/')"
curl -fsSL "https://github.com/wukongnotnull/vole/archive/refs/tags/v${VERSION}.tar.gz" | shasum -a 256
```

把输出写入 formula 的 `sha256`。

- [ ] **Step 3: Local install from source using candidate**

```bash
brew install --build-from-source "./docs/homebrew/vole-homebrew-core.rb"
unset VOLE_RULES_DIR
vole --help
ls "$(brew --prefix vole)/share/vole/rules" | head
```

Expected: 安装成功；rules 目录非空；无需 env。

耗时长（Rust 编译）；`block_until_ms` 要给足。若与自建 tap 冲突，先 `brew uninstall vole`。

- [ ] **Step 4: Audit**

```bash

```

把摘要贴进 findings。已知可能警告（新 formula 命名、livecheck 等）逐条记下是否阻塞。
