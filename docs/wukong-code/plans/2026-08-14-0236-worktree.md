# `vole worktree` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use wukong-code:executing-plans（本仓默认 inline）或 wukong-code:subagent-driven-development。Steps 用 checkbox（`- [ ]`）跟踪。

**Goal:** 交付顶层命令 `vole worktree`：盘点官方 Git worktree 与 Agent 容器 checkout，启发式排序后由用户确认，将整棵目录送入废纸篓并 `git worktree prune`；Home 菜单增加第 6 项。

**Architecture:** 镜像 `purge`：`vole-core::ops::{worktree_plan,worktree_apply}` 产出/消费 `ProtoPlan`（`rule_id` 前缀 `worktree:`）。Git 经可注入 `GitProbe`；删除只走 `mole_delete_verified`。`vole-cli` 薄前端（plan/apply/TTY 多选默认全不勾选）。不走 clean 规则 TOML，不并入 `purge`。

**Tech Stack:** Rust workspace、`vole-proto` schema 1、本机 `git`（超时子进程）、`jwalk` 计量体积、clap + 现有 paginated select。

**Design:** [`../specs/2026-08-14-0228-worktree-design.md`](../specs/2026-08-14-0228-worktree-design.md)

## Global Constraints

- 不宣称可安全删除：UI / JSON / `--help` 不得出现 `safe` / `deletable` / 「可安全删除」
- 删除只走 `mole_delete_verified`；登记只走 `git worktree prune`（用户已确认的 locked 才 `unlock` 再 prune）；禁止 `rm -rf`、禁止 `git worktree remove`、禁止 `git branch -d`
- 不删主工作区、不删 cwd 所在 worktree；plan 与 apply 都要再查
- 不 bump `schema_version`；不改正式版本号、不发版
- Mole required 命令面不加入 `worktree`；`--enforce` 不因缺少它而失败
- TTY 多选默认全不勾选
- 每个 `git` 子进程必须有 wall-clock 上限（`vole_sys::timeouts::MEDIUM_PROBE` 或 `PKG_LIST`）
- TDD：先红测再实现；每 Task commit
- 合入用 merge commit（非 squash）
- `vole-core` / `vole-cli` 测试在 macOS 上跑

```rust
pub trait GitProbe {
    fn worktree_list(&self, repo: &Path) -> Result<String, String>;
    fn status_porcelain(&self, worktree: &Path, ignored: bool) -> Result<String, String>;
    fn log_unpushed(&self, worktree: &Path) -> Result<String, String>;
    fn last_commit_unix(&self, worktree: &Path) -> Result<Option<i64>, String>;
    fn rev_parse_toplevel(&self, cwd: &Path) -> Result<PathBuf, String>;
    fn prune(&self, repo: &Path) -> Result<(), String>;
    fn unlock(&self, repo: &Path, worktree: &Path) -> Result<(), String>;
}
```

`LiveGitProbe` 用 `std::process::Command` + 与 `login_items::run_command_timeout` 相同的轮询 kill 模式：

| 方法 | argv | 超时 |
|---|---|---|
| `worktree_list` | `git -C <repo> worktree list --porcelain` | `PKG_LIST` |
| `status_porcelain` | `git -C <wt> status --porcelain`；`ignored==true` 时加 `--ignored` | `MEDIUM_PROBE` |
| `log_unpushed` | `git -C <wt> log HEAD --not --remotes --pretty=%H` | `MEDIUM_PROBE` |
| `last_commit_unix` | `git -C <wt> log -1 --format=%ct` | `SHORT_QUERY` |
| `rev_parse_toplevel` | `git -C <cwd> rev-parse --show-toplevel` | `SHORT_QUERY` |
| `prune` | `git -C <repo> worktree prune` | `PKG_LIST` |
| `unlock` | `git -C <repo> worktree unlock -- <path>` | `MEDIUM_PROBE` |

超时或非 0 → `Err`；调用方 fail-closed。

**发现算法（钉死）：**

1. 搜索根 = `opts.search_roots` 或 purge 同等根（含 HOME 一层项目容器）。**另外**把 `opts.git.rev_parse_toplevel(opts.cwd)` 成功时的仓库根加入。
2. 在每个根下找 Git 仓库：`jwalk` max_depth 6，目录含 `.git`（文件或目录）；跳过 basename ∈ `PURGE_TARGETS` 的目录及其子树。
3. 来源 A：对每个仓库 `worktree_list`。porcelain **第一条**视为主工作区，丢掉。路径规范化后等于 `opts.cwd` 的 canonicalize（或 cwd 位于该 worktree 路径之下）→ 丢掉。`prunable` 或路径不存在 → `WorktreeKind::Stale`，size=0。否则 `Linked`。
4. 来源 B：若存在则扫 `home/.codex/worktrees/*`、`home/.claude/worktrees/*`、每个已发现仓库的 `.worktrees/*` 与 `.claude/worktrees/*`。子项须含 `.git`。路径已在 A 出现则合并。否则 `OrphanDir`；若 `.git` 文件内容匹配 `gitdir: <abs>` 且该 abs 含 `/.git/worktrees/`，主仓为那之前的路径。
5. 硬排除后再算阻塞项（仅目录仍在的）：
   - `status_porcelain(false)` 非空 → `dirty`；`Err` → `status-unknown`
   - `status_porcelain(true)` 中 `!! ` 行的 basename **不在** `PURGE_TARGETS` → `ignored-keep`
   - `log_unpushed` 非空 → `unpushed`
   - porcelain `locked` → `locked`
6. 年龄：`last_commit_unix`；失败则 checkout 根 `symlink_metadata.modified()`。
7. 体积：`jwalk` max_depth 4 文件 len 之和；失败则 0。
8. 转 `ProtoPlanEntry`：`id = worktree:{kind}:{canonical-path}`；`rule_id` 用 `rule_id_for`；`label` 用 `format_worktree_label`；`blockers` 拷贝；有目录则抓 identity，stale 则 `dev=ino=0`，`mtime=UNIX_EPOCH`。`validate_path_for_deletion` 失败的 linked/orphan **不进 plan**。stale 无目录，跳过路径校验。
9. `coverage_note` 固定为：

```text
worktree scan skips Conductor-style deep containers; positive removal verdicts are out of scope.
```

（可在其后追加 `skipped N git repo(s) on timeout.`）测试断言 `contains("conductor")` 且 `contains("positive removal verdicts")`。JSON 对象不得有 `safe` / `deletable` 键。

2. `rule_id` 不是 `worktree:linked` / `worktree:stale` / `worktree:orphan-dir` → skipped

6. linked/orphan：TOCTOU `verify_plan_entry_for_apply`；失败 skipped。然后 `mole_delete_verified`。成功后再 `git.prune(repo)`。若 prune 失败且 blockers/label 含 `locked`，`git.unlock(repo, path)` 再 prune。prune 仍失败 → failed（不得标 succeeded），不从废纸篓搬回
