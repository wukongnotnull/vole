- 对照：`bin/purge.sh`、`lib/clean/project.sh`、`lib/clean/purge_shared.sh`

## 1. 结论

交付 **`vole purge`** 高对齐主路径：项目构建物发现 → `--plan` → `--apply`；JSON；保护层；默认废纸篓；菜单与补全。  
编排在 `vole-core::ops`；`vole-cli` 薄前端。镜像 **uninstall/optimize** 的 ProtoPlan 漏斗，**不**走 clean 规则 TOML。  
同 PR 交付 §3.3 别名：`completion` / `optimise` / `analyse`，使 `2.0.0` 具备完整命令名兼容。

## 2. CLI 面

| Flag | 行为 |
|---|---|
| （默认）/`--plan`/`--dry-run`/`-n` | 只产出候选，不删 |
| `--apply PLAN` | TTL + TOCTOU + 漏斗删除 |
| `--permanent` | 仅与 `--apply`；永久删 |
| `--json` / `--json-stream` / `--plan-out` | 同 uninstall |
| `--include-empty` | 纳入零大小产物目录（对齐 Mole；默认跳过空目录可省噪） |
| `--paths`（可选本里程碑） | **长尾**：配置编辑 UI 可延后；若未做，支持读 `~/.config/vole/purge_paths`（一行一路径）即可 |

交互菜单增加 `purge --plan`。Shell 补全随 clap `Command::Purge` 自动生成。

## 3. 发现与候选

### 3.1 Targets（钉死 Mole 表）

完整复制 `MOLE_PURGE_TARGETS`（钉版约 35 项，含 `node_modules`/`target`/`build`/`dist`/…/`Pods`/`DerivedData` 等）。禁止本 PR 盲扩新 basename。

### 3.2 搜索根

1. 若存在 `~/.config/vole/purge_paths`（或 env `VOLE_PURGE_PATHS` 测试注入）：使用所列绝对/相对 `$HOME` 路径  
2. 否则默认：Mole `MOLE_PURGE_DEFAULT_SEARCH_PATHS`（`www`/`dev`/`Projects`/…/`CloudStorage`/`.codex/worktrees`/`.claude/worktrees`）中**存在**的目录  
3. 另：扫描 `$HOME/*/` 一层，对通过「项目容器」启发式（含 `package.json`/`Cargo.toml`/`.git` 等 Mole indicators 子集，maxdepth 2）的目录纳入搜索根  
4. **禁止**把整个 `$HOME` 当作无界根盲目深扫；点目录容器仅显式列表

### 3.3 匹配与年龄

- 在每个搜索根下找 basename ∈ targets 的目录（max depth 默认 6，min depth 1）  
- `MIN_AGE_DAYS = 7`：目录 mtime 距今 < 7 天 → 跳过（uncertain/失败 → **fail-closed 跳过**，对齐 Mole「超时不当 old」精神的简化）  
- `is_protected_purge_artifact` 移植要点：`bin`（仅 .NET 上下文可删）、`vendor`（非 Composer 保护）、全局 `~/Library/Developer/Xcode/DerivedData` 保护  
- 路径须过 `validate_path_for_deletion` + `AppProtection`（Cleanup 模式）

### 3.4 Plan 契约

- `schema_version`：**不 bump**（复用 1）  
- `rule_id`：`purge:{target}` 或 `purge:{target}:{stable-suffix}`（suffix 避免同 target 多路径冲突；`id` 仍用 path 区分）  
- `ttl_secs`：900（同 uninstall）  
- `coverage_note`：诚实记录未移植长尾（完整 activity 分类、cloud 确认交互等；TTY 多选已由 T1 / 2.8.0 落地，勿再写入「无 TTY 多选」）

## 4. Apply

- 独立 `apply_purge_plan`：仅接受 `rule_id` 前缀 `purge:`  
- 默认 `DeleteMode::Trash`；`--permanent` → Permanent  
- 每条目：`verify_plan_entry_for_apply` → `mole_delete_verified`  
- oplog `command = "purge"`；互斥 `try_lock_config("purge")`  
- **禁止**平行 `rm -rf`

## 6. 明确不做（本里程碑）

- TTY 分页多选 UI  
- 完整 Mole `classify_purge_activity` 全部分支（用 mtime 年龄简化 + fail-closed）  
- 云同步交互确认全量复刻（非交互：跳过明显 iCloud 路径或 coverage 注明）  
- `hints` 模块（M6）  
- installer/touchid/update/remove  
- 空 bump：仅功能就绪后改 `2.0.0`

## 7. 测试与验收

- 单元：`purge_plan` 发现/年龄/保护；`purge_apply` 拒绝非 `purge:`  
- CLI：`purge --plan --json` 在 temp HOME 含陈旧 `node_modules` 时产出条目；`--apply` + `MOLE_TEST_TRASH_DIR`  
- 别名：`vole optimise --help` / `analyse` / `completion` 退出 0  
- `scripts/check-command-surface.sh --enforce`：至少清除 `purge` 与三别名缺口（其余五命令仍可缺，收口再强制全集——**或** stub 保持 report；M5 后 enforce 对已交付子集可另加。本 design：M5 验收跑 report-only 确认 `purge`/`optimise`/`analyse`/`completion` 不再 MISSING）  
- 版本：`Cargo.toml` workspace = `2.0.0`；`docs/releases/v2.0.0.md`；Formula/README 同步
