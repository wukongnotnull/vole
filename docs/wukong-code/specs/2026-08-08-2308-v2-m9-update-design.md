# Vole M9：自更新 `update` 设计

- 日期：2026-08-08 23:08
- 状态：已批准（会话默认批准；产品 v2 续篇权威规格下的专用 design）
- 包版本：本里程碑发版 **`2.4.0`**（规格 §5：M9 → MINOR）
- Mole 钉版：`third_party/mole-1.48.1`
- 依据：[`2026-08-08-2030-v2-cli-complete-design.md`](2026-08-08-2030-v2-cli-complete-design.md) §5 / §6.5；M4 findings [`../../findings/2026-08-v2-m4-cli-complete-spike.md`](../../findings/2026-08-v2-m4-cli-complete-spike.md) §3.5
- 对照：`lib/manage/update.sh` + `install.sh`（checksum / attestation fail-closed）

## 1. 结论

交付 **`vole update`：自更新通道**（检测 → 下载 → 校验 → 安装），**非**仅 `brew upgrade` 包装。  
编排在 `vole-core::ops`（含与 M10 共享的安装来源判定）；`vole-cli` 薄前端。  
校验失败 **fail-closed**；禁止因校验失败静默降级到未校验源码安装。  
成功以安装后目标二进制的 `vole --version` 为准。  
功能就绪后 bump **`2.4.0`**；不得空 bump。

## 2. CLI 面

| 形态 | 行为 |
|---|---|
| `vole update` | 稳定通道：查最新 GitHub Release →（若需）下载 / 校验 / 安装 |
| `vole update --check` | 只读：报告当前版本、最新版本、安装来源；**不**下载不安装 |
| `vole update --force` / `-f` | 即使已是最新也重装；brew 管理安装时**跳过**「优先 brew」拦截，进入自更新通道 |
| `vole update --nightly` | 显式 nightly 通道（见 §5）；brew 管理安装 **拒绝** |
| `--json` | 结构化输出（check / 结果） |
| `--yes` / `-y` | 非交互确认（brew 自更新确认；等同肯定答复） |

Flag 名称锁定：`--force` / `-f`、`--nightly`、`--check`（只读检查形态）、`--yes`/`-y`。  
交互菜单（裸 `vole`）增加 `update` 入口，仅 spawn 本地 `update --check`（**不**在菜单渲染前联网）。  
Shell 补全随 clap `Command::Update` 自动生成。

**裸调用不联网（硬约束）：** `vole` 无子命令 → `interactive::run()`，**禁止** Mole 式 `check_for_updates`。`scripts/check-command-surface.sh` 已有静态闸门，本里程碑保持绿。

## 3. 安装来源判定（与 M10 共享）

模块：`vole-core::ops::install_origin`（本里程碑落地；M10 复用）。

| `InstallOrigin` | 判定（按调用中的可执行文件路径，默认 `current_exe`，可注入） |
|---|---|
| `Homebrew` | 路径为指向 `*/Cellar/vole/*` 的 symlink；或规范路径为 `/opt/homebrew/bin/vole` / `/usr/local/bin/vole` 且对应 `Cellar/vole` 存在（可选再确认 `brew list vole`，失败不推翻路径证据） |
| `Manual` | 能解析路径且非 Homebrew |
| `Unknown` | 无法解析路径 |

同时产出：

- `binary_path: PathBuf`
- `prefix_bin: PathBuf`（dirname of binary；安装替换目标）
- `config_dir`：`$VOLE_CONFIG_DIR` 或 `$HOME/.config/vole`（写 `install_channel`）

**不**跟 PATH 上「另一个 vole」；始终跟当前进程可执行文件（对齐 Mole `MOLE_ENTRY_SCRIPT` / `resolve_mole_source_path`）。

## 4. 稳定通道流程

```
resolve origin + binary
    → --check? 只报告后退出
    → Homebrew 且无 --force/--yes? 提示优先 `brew upgrade vole`，退出（不下载）
    → Homebrew 且 --nightly? 错误退出
    → 发现最新稳定 tag（GitHub releases/latest；失败可回退读仓库 Cargo.toml 版本字段，仍失败则报错）
    → 已最新且无 --force? 成功退出「Already on latest」
    → 下载 `vole-{ver}-{arch}.tar.gz` + `SHA256SUMS`
    → 校验（§6）；失败 → abort，绝不源码降级
    → 解压到临时目录；将 `bin/vole`（及同包 `share/vole/rules` 若存在）安装到当前 prefix
    → 运行安装后二进制 `--version`，token 必须等于目标版本
    → 写 `install_channel` CHANNEL=stable；清更新缓存（若有）
```

网络与下载：通过可注入 `UpdateTransport` trait（生产默认 `curl -fsSL`；测试 Fake）。禁止在单元测试里打真网。

Arch 资产名：`aarch64-apple-darwin` / `x86_64-apple-darwin`（与 `scripts/package-release.sh` 一致）。  
仓库：`https://github.com/wukongnotnull/vole`（可由 `VOLE_UPDATE_REPO` 覆盖，仅测试）。

## 5. `--nightly`

- **仅 Manual / Unknown**；Homebrew → 明确错误（对齐 Mole）。
- 解析 `main` 最新 commit SHA（GitHub commits API）。
- 与 `install_channel` 中 `COMMIT_HASH` 前 7 位相同且无 `--force` → 「Already on latest nightly」退出。
- 安装路径：**显式**用户选择了 `--nightly` 后，允许从 `main` 拉取 `install.sh` 并在本机 `cargo` 构建安装（loud warning：`nightly source install; not checksum-attested`）。  
  **禁止**把该路径当作「稳定通道 checksum 失败」的回退。
- 成功判据：安装后 `--version` 可执行且写回 `CHANNEL=nightly` + `COMMIT_HASH=<sha>`；版本号可能仍为 workspace 版本，不以 tag 对齐为硬条件，而以「二进制已替换且 channel 元数据已写」+ 可执行 `--version` 为准。
- 无 `cargo` / 构建失败 → 失败退出；不静默改走未声明通道。

## 6. 校验（fail-closed）

| 规则 | 行为 |
|---|---|
| 稳定通道必须取得 `SHA256SUMS` | 缺失 / 下载失败 → **abort** |
| tarball sha256 必须命中 SUMS 中对应资产行 | 不匹配 → **abort** |
| attestation（可选增强） | 若环境有 `gh` 且 `VOLE_REQUIRE_ATTESTATION=1`：对 SUMS 做 `gh attestation verify`；失败 abort。默认不强制（与 Mole「无 gh 则 checksum-only」对齐） |
| 稳定通道校验失败 | **禁止**回退源码 / `install.sh \| bash` / nightly |
| 自愈 | 本里程碑**不做** Mole `_update_self_heal_reinstall`（该路径易变成未校验后门）；安装失败即失败，提示手动重装 URL |
| 成功判据 | 安装后 `"$binary" --version` 首行末 token == 目标版本（稳定）；不以安装器 stdout 为准 |

发版支撑（本里程碑必做）：

- `scripts/package-release.sh` 生成 `dist/SHA256SUMS`（对两个 arch tarball）
- `release.yml` 上传 `SHA256SUMS` 与 tarball

## 7. Homebrew 共存（写死）

| 场景 | 行为 |
|---|---|
| Homebrew + 默认 `vole update` | **不**跑自更新下载；打印优先 `brew upgrade vole`；`--check` 仍可报告 GitHub latest 与 origin=`homebrew` |
| Homebrew + 交互 TTY 且用户确认自更新 | 允许进入稳定自更新通道（覆盖当前 bin；并 warning 可能与 brew 打架） |
| Homebrew + `--force` 或 `--yes` | 同上，跳过提示直接自更新 |
| Homebrew + `--nightly` | 错误：请改用脚本安装或去掉 brew 管理 |
| 非 Homebrew | 正常自更新通道 |

说明：`--force` 在非 brew 上表示「强制重装」；在 brew 上**同时**解除 brew 拦截。不把 `vole update` 实现成自动 `brew upgrade`（避免变成包装器）；提示文案引导用户用 brew。
