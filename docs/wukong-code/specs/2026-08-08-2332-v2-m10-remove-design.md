## 1. 结论

交付 **`vole remove`：自卸载**。  
复用 M9 `vole-core::ops::install_origin`；编排在 `vole-core::ops::remove`；`vole-cli` 薄前端。  
`--dry-run` 列全待删项；默认交互确认；仅删 Vole 自身产物与自身配置。  
Homebrew：**提示并经确认后调用** `brew uninstall vole`，**禁止**手撕 Cellar / brew prefix 二进制。  
删除一律走既有路径校验 + `safe_remove` / 漏斗；**禁止**绕过校验的裸 `rm -rf`。  
功能就绪后 bump **`2.5.0`**；不得空 bump。

## 2. CLI 面

| 形态 | 行为 |
|---|---|
| `vole remove` | 探测安装形态 → 列出待删项 → **交互确认** → 执行 |
| `vole remove --dry-run` / `-n` | 列全待删项（含 brew 提示行）；**不**确认、**不**删除、**不**调 brew |
| `vole remove --yes` / `-y` | 跳过交互确认（脚本/CI） |
| `--json` | 结构化输出探测结果 / dry-run 清单 / 执行结果 |
| `--purge-oplog` | **显式**才删除 Mole 兼容审计日志（见 §5）；默认保留 |

Flag 名称锁定：`--dry-run`/`-n`、`--yes`/`-y`、`--json`、`--purge-oplog`。  
交互菜单增加 `remove --dry-run` 入口（只读预览，避免菜单误卸）。  
Shell 补全随 clap `Command::Remove` 自动生成。  
`scripts/check-command-surface.sh`：`remove` 不再 MISSING。

## 3. 三类安装形态（硬约束）

探测以**当前进程可执行文件**为主（`current_exe` / `VOLE_UPDATE_EXE` 注入，对齐 M9），并扫描固定候选路径；**不**误删 brew Cellar symlink 目标。

| 形态 | 探测 | dry-run / 执行 |
|---|---|---|
| **Homebrew** | `detect_install_layout(...).origin == Homebrew`；或（非测试）`brew list vole` 成功（失败不推翻路径证据） | dry-run：`Would run: brew uninstall vole`；执行：调用 `brew uninstall vole`（可注入）；**永不**对 `*/Cellar/vole/*` 或 brew `bin/vole` symlink 走文件删除漏斗 |
| **手动前缀安装** | 当前 exe 为 Manual；另扫 `/usr/local/bin/vole`、`$HOME/.local/bin/vole`、`/opt/local/bin/vole`（存在且非 Cellar symlink）；同 prefix 的 `share/vole`（规则树）若存在则入清单 | 经漏斗删除列出的二进制与 `share/vole` |
| **shell alias / 补全残留** | 固定候选：`$HOME/.local/bin` 等处的非 Cellar 短名包装（若存在同名文件且内容/链接指向 vole）；以及若存在则纳入：`~/.config/fish/completions/vole.fish`、bash/zsh 常见用户补全落点中的 `vole` 补全文件（仅文件名精确匹配 `vole` / `_vole`，禁止扫整棵 shell rc） | 经漏斗删除清单内文件 |

无任何 Homebrew / 手动 / 残留 / 自身配置命中 → 成功退出「No Vole installation detected」（对齐 Mole）。

## 4. 删除白名单（逐项写死）

**默认会删（存在才列/删）：**

| 项 | 路径规则 |
|---|---|
| 手动二进制 | §3 手动前缀清单中的 `vole` 文件（非 Cellar） |
| share 规则树 | 与手动二进制同 prefix 的 `share/vole`（目录） |
| alias / 补全残留 | §3 第三类精确路径 |
| 自身配置 | `$VOLE_CONFIG_DIR` 或 `$HOME/.config/vole` |
| 自身缓存 | `$HOME/.cache/vole`（含 mutex 等） |
| 自身日志目录（若存在） | `$HOME/Library/Logs/vole` |

**默认不删（除非显式 flag）：**

| 项 | 路径 | Flag |
|---|---|---|
| Mole 兼容 oplog / 审计 | `$HOME/Library/Logs/mole/operations.log`、`deletions.log`（及该目录下 vole 写入的同族日志） | `--purge-oplog` 才删这些文件；**不**递归清空无关第三方内容时仍只删上述已知文件名 |
| 用户数据 | 文档、下载、应用数据、其它 brew 包 | **永不** |
| Homebrew Cellar / cellar symlink | `*/Cellar/vole/*`、`brew --prefix`/bin/vole | **永不手撕**；只走 `brew uninstall` |

## 5. 流程

```
resolve layout (install_origin) + scan candidates
    → build RemovePlan { brew: bool, paths: [...], oplog_paths: [...] }
    → --dry-run? 打印全部 Would … 后 exit 0
    → 无目标? 「No Vole installation detected」exit 0
    → 交互确认（非 --yes；非 TTY → 要求 --yes，否则 exit 2）
    → brew? 调用 brew uninstall vole（失败记错 + 打印手动步骤，继续其它项）
    → 对其余 paths：validate_path_for_deletion → safe_remove（永久删除；自卸载不对废纸篓，对齐 Mole rm）
    → --purge-oplog? 同样漏斗删 oplog 文件
    → 汇总成功 / 部分错误
```

**删除漏斗（硬约束）：**

- 每个文件/目录路径必须先 `validate_path_for_deletion`（或等价既有闸口）
- 实际删除调用 `safe_remove` / `FsRemover`（或已有 verified 封装）
- **禁止**在 `ops/remove` 或 CLI 中直接 `std::fs::remove_dir_all` / `Command::new("rm")` 作为生产路径
- brew 卸载是包管理器 API，不是路径删除，单独走 `BrewUninstaller` trait

## 6. Homebrew 行为（写死）

| 场景 | 行为 |
|---|---|
| 判定 Homebrew | 清单含 brew 行；**不**把 Cellar 路径加入 `paths` |
| dry-run | 打印 `Would run: brew uninstall vole` |
| 确认后执行 | 调用注入的 `BrewUninstaller`（生产：`brew uninstall vole`）；失败 → 错误信息 + `Manual step: brew uninstall vole` |
| brew 不在 PATH | 不猜测撕 Cellar；只打印手动步骤 |
| 同时存在手动副本 | brew 走卸载命令；手动副本仍可经漏斗删除 |

**不**使用 `brew uninstall --force` 作为默认（比 Mole 更克制）；若未来需要再开 flag，本里程碑不做。

## 7. 可测性

| 注入点 | 用途 |
|---|---|
| `VOLE_UPDATE_EXE` / API `binary_path` | 伪造 Homebrew / Manual layout |
| 临时 `$HOME` / `VOLE_CONFIG_DIR` | 配置、缓存、补全、oplog fixture |
| `BrewUninstaller` Fake | 断言调用次数与参数；不碰真 brew |
| `VOLE_TEST_NO_AUTH=1` | 不触发交互 sudo；不可写路径 → 记错，不挂起 |
| `--yes` | 非 TTY 确认 |

单元覆盖：三类形态 dry-run 清单、brew 不进 paths、手动删除走漏斗、默认保留 oplog、`--purge-oplog` 才删、无安装、校验失败路径不删、Cellar 路径拒绝。

## 8. 明确不做（本里程碑）

- 手撕 Homebrew Cellar
- 默认删除 oplog / 用户数据
- 扫描并改写用户 `.zshrc`/`.bashrc` 内 alias 行（只删独立补全/包装文件）
- 与 `uninstall`（卸第三方 App）混用语义
- Linux / MAS
- 空 bump
- 命令面收口 enforce（属收口里程碑；本里程碑只让 `remove` 从 MISSING 消失）
